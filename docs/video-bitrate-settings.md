# 视频码率设置

屏幕弹窗、高级显示设置和声明 `video.settings = "all"` 的扩展共用
`VideoBitrateControl`。H.264/H.265 的“码率预算上限”以 Mbps 显示档位和自定义值，
配置与 API 使用整数 `video.h26x.bitrate_kbps`；1 Mbps = 1000 kbps，自定义精度为 0.001 Mbps。

- 正数设置 VBR 软上限，没有可配置的实际码率下限。静态画面可使用更低码率，
  复杂帧和关键帧可能短时超过预算。
- “自动”保存为 0。网页立即开始播放，通过实际媒体流的持续反馈调整运行时上限，
  不再阻塞首帧测速。WebRTC 使用 TWCC 到达时间／丢包与 RR 兜底，WebSocket 使用
  实际视频帧送达确认和积压；静止桌面的低码率不会直接被当作带宽不足。
- 多观看者共用一个硬件码流，最先登记的自动码率观看者控制共享上限，断开后移交
  下一位。慢速旁观者不降低主会话画质，但可能跳帧或等待关键帧。
- 主视频从 `video_bitrate_kbps` schema 读取可设范围和步进；扩展从
  `bitrate_kbps` 设置 schema 读取范围。未报告范围时禁用绝对码率设置并显示原因。
  范围的最小值是上限参数的最小可设值，不代表实际码率下限。
- 配置接口透传当前已加载后端描述中的范围，不由界面猜测。SG200x 为
  0.1–10 Mbps，AX630C 为 0.1–50 Mbps；两者步进均为 0.1 Mbps。
- 独立高级设置页关闭视频会话后，按配置接口的 `video_settings_writable` 判断
  是否允许编辑；窗口版仍沿用当前观看会话的主客户端权限。跳转前等待会话关闭，
  避免把自己的旧会话误判为其他主客户端。保存时后端再次检查主会话归属。
- 选择正数上限会清除显式 QP 参数；选择画质预设会把码率上限切回“自动”。
  弹窗依次清除 QP 后再写入上限，避免旧 QP 限制影响码率控制。
- MJPEG 的百分比只表示 JPEG 压缩画质，独立于 H.264/H.265 的码率上限。

屏幕弹窗的码率、画质预设和 EDID 说明共用 `DisplaySettingHelp`，支持鼠标悬停、
键盘聚焦、触屏点击及 Escape 关闭。扩展中的组合视频控件使用有名称的分组，
避免原生 `label` 将选择器点击转给同组数值框。

自适应上限只保留在内存中，不写入持久配置。手动正数码率不参与自动调整。
自动上限生效时，运行时暂不使用显式初始／最小／最大 QP，避免旧的画质约束阻止
编码器降码率；所存参数保持不变，最后一个自动会话移除后恢复。

性能面板的码率单元格（含紧凑栏）支持悬停或键盘聚焦查看已设置的码率上限。自动模式还会显示本 WebRTC 连接当前的自适应上限；共享编码器的实际限制由首位自动观看者决定。MJPEG 或旧服务端未提供上限时显示“—”。
